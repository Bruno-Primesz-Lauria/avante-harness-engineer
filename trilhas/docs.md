# Documentação

Usar quando: escrever ou atualizar documento útil ao leitor, com afirmações sustentadas.

## Passos

1. **Ler.** Confira as fontes vivas e resolva divergência relevante. Feito quando: as fontes são rastreáveis.
2. **Escrever.** Use o arquivo exato do contrato. O caminho vem do repositório, não de pasta de runtime. Feito quando: o texto está fiel e acionável.
3. **Inspecionar.** Cheque fato, link, legibilidade e duplicação. Suíte de produto não é obrigatória. Feito quando: o aceite documental está registrado.
4. **Revisar.** Entre no [laço comum](README.md). Achado procedente volta ao texto, dentro do orçamento. Feito quando: não há achado obrigatório aberto.

Com agentes: `docs` escreve no passo 2; a inspeção do passo 3 é sua; `refute` revisa no 4. Achado procedente volta a `docs` e pede nova inspeção e nova revisão.

## Aceite

Superfície: os documentos nomeados no contrato.

Precisão, links e utilidade para o leitor. Afirmação factual sobre código é conferida no código.

## Fecho

`DONE` se o aceite documental fechou. `REVIEW` só se uma revisão humana faz parte do acordo.
